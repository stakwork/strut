# Human steps and the task store

People as a step of a workflow: the task store, workers, and the worker's steps.

This file is the reference for one area of strut; [AGENTS.md](../AGENTS.md) is the
index. A change in this area updates this file, not AGENTS.md.

## Key concepts

- **The task store — people as a step of a workflow** (`plans/human-steps.md`
  §4, item 2a; `src/tasks/`). A `human` step (item 2b) makes a TASK keyed by
  its workflow, run id and step path and parks its run; a WORKER signed in to
  the worker app takes the next task of a type an admin granted them, answers
  it, and the answer settles the task. Strut's own SQLite file
  (`<dataDir>/tasks/tasks.db`, the ledger's pattern), never an app's SQL: a
  worker reaches a task only through their own LEASE, one live at a time, one
  answer per lease checked against the type's answer schema (a subset strut
  checks itself, `answer-schema.ts`; a type whose schema uses anything else is
  refused when saved). The worker is the actor the CALLER passes, never an
  argument, and their status and grants are read on every call; suspending or
  banning one expires their lease at once. A sweep every minute frees dead
  leases and expires tasks past their `withinHours`; `onSettle` hears every
  task that leaves `open`, which is how item 2b wakes runs. Two modules: the
  task side and the worker side, so the workers may one day be managed
  elsewhere.

## Files

What each file and folder in this area is, in the order of the tree.

### `src/tasks/`

the TASK STORE (plans/human-steps.md §4, item 2a; the `human` step that parks on it is item 2b, the worker's `task/*` steps and the staff's routes item 3, §5–§6, earnings item 5a, §8.1): people as a step of a workflow, in the ledger's pattern. answer-schema.ts: the answer's shape, PURE — a JSON Schema SUBSET strut checks itself (`type` on every schema; `properties` + `required`, a key the schema does not name refused; `items`, `minItems`, `maxItems`; `enum`; `minimum`, `maximum`; `minLength`, `maxLength`; `title` / `description` as labels), `answerSchemaProblem` (a type's schema, refused when it uses anything else, a keyword on a type it does not apply to, or an `enum` option that does not fit) and `answerProblem` (an answer: nesting to 8, 256 KB as JSON). task-store.ts: the TASK side — `task_types` (app, answer schema, `leaseSeconds` 600, `withinHours` 72, enabled, `paySats` — sats to the msat an answer earns, unpaid when absent — and `holdHours` 72), `tasks` (a random id, unique on workflow + run id + step path, `show`, `files` + `root` run | job, status `open` / `settled` / `expired` / `cancelled`, `due`, the answer and `by`), `leases` (128 random bits, one per task and worker ever, `open` / `submitted` / `expired` / `skipped`; LIVE while open and before its expiry, so nothing waits on the sweep to be right; `payMsat`, the type's pay STAMPED by `take`, and `bookedAt`, when its earning reached the ledger); `TaskStore` with the guarded writes — `take` (rule 2: the oldest open task not past due of a type asked for and enabled, that this worker never held and nobody holds, while the worker holds nothing live: ONE statement on the file), `settle` (the lease submitted and the task settled, both guarded, one transaction at `synchronous=full`), `skip`, `release`, `cancel`, `sweep`, `booked` / `unbooked` (submitted leases with pay and no `bookedAt`, a partial index) — and `MemoryTaskStore`. Pay's four columns are added by `ALTER TABLE` when a file lacks them, `user_version` still 1, so a file from #655 opens as it is. worker-store.ts: the WORKER side — `workers` (status `new` / `active` / `suspended` / `banned`, first seen, a note) and `grants` (one row per worker and type, revoked when and why), `liveGrants`, `MemoryWorkerStore`; it knows nothing of tasks (ruling 5 may move it). db.ts: `<dataDir>/tasks/tasks.db`, owner-only folder, WAL, every write one `BEGIN IMMEDIATE`, `close()` folds the WAL; task-store-sqlite.ts and worker-store-sqlite.ts keep their own tables in it. tasks.ts: the service — `createTasks({ open, exists?, now?, ledger?, ledgerIfAny?, usdPerBtc? })`, `openTaskStores` (imports `node:sqlite` on first use) / `memoryTaskStores`, `TaskError` (a code first); its frozen `capability` is the WHOLE store, which the staff routes hold and no services bag carries (plans/human-steps.md §9.2): `ensure` (the `human` step's: the task by key, made only of an enabled type, `show` ≤ 256 KB, ≤ 200 files under the run's files), the worker's `next` / `submit` / `skip` / `file` / `me` for the ACTOR the caller passes and the calling `app` (status and grants read on every call: only `active` takes tasks; `next` narrows by `type` and `app`, returns the worker's live lease again, `{ none: true }` when there is nothing, hands out the type's `answer` schema and the lease's `payMsat`, and with `wait` (≤ `NEXT_WAIT_MAX_S`, 25) HOLDS for a task — woken by a task made or skipped (the oldest waiter of that type, which hands the wake on if it takes nothing), a grant, a revoke or a status change (that worker's), the sweep freeing leases or a type saved (every waiter once); `submit` checks the answer against the type's schema and settles the task, then BOOKS a paid lease's earning (§8.1: the ledger's `pay`, one row per lease, its `releases` the answer's time plus the type's hold as booked; then `bookedAt` here) — a booking that fails is logged, never the worker's, and the sweep books it; `me` adds `balance` (`heldMsat`, `withdrawableMsat`, `totalMsat`, `nextReleaseAt?`, read through `ledgerIfAny`, zeros and no file with nothing earned) and each type's `payMsat`; `submit`, `skip` and `file` refuse a lease of a type another app draws, `wrong_app`; `file` reads one path on the task's `files` through the caller's live lease, `not_listed` otherwise, through `deps.file` — createStrut's reads where `run/files` would; each worker makes at most `TASK_CALLS_PER_MINUTE` (120) calls a minute, a held wait counted once, `too_many`), the staff's `types` / `setType` (a PUT; `paySats` 0 to 1,000,000, `holdHours` 1 to 720) / `deleteType` (`in_use` while a task of it is open; revokes its live grants) / `workers` (each with its `balance`, one grouped read) / `setWorker` (`suspended` or `banned` expires the worker's live lease at once) / `grant` (`new` → `active`) / `revoke` (expires a live lease of that type; the status stays) / `list` / `task` (with leases, an answered one with its ledger `earning`); `ensure` answers a settled task with its `pay: { msat, usd? }` (the lease's stamp, dollars at `usdPerBtc` now). The service also has `human` (`ensure` alone, frozen: every step's `ctx.services.tasks` on the SHARED bag, so no step, workflow, agent tool, proposal apply or release step reaches a worker's call — which takes any actor — or the staff's; a host's own `services.tasks` is kept as it is), `worker` (the worker's calls alone, frozen: what a `worker: true` step's OWN call bag carries on both app doors — `workerServices`, src/apps/tools.ts — never the shared bag) and `isActiveWorker(actor)` (from memory: the active workers loaded when the store opens and kept by every write — what the public routes count a request under). Beside it, for 2b's `task` source: `onSettle` (tasks that left `open` — answered, swept as expired, cancelled), `settled(id)`, `cancel(id)`, `cancelRun(workflow, runId)`; `takeBack({ task, worker?, why, by? })` (§8.1: each answer's earning taken back while held — `taken`, `released` past its hold, `none` — booking one not booked first; the service's alone, never a capability's); `sweep` (rule 8, and books what `submit` did not) and `start` (the sweep now and every minute, only where a store is open or on file). No file until something is asked of it, and a staff read on a strut without one answers empty. createStrut builds it (`strut.tasks`; memory where the run store is), closes it in `close()`. The store is the `task` SOURCE of parked runs (`TASK_PARK_PREFIX`, registered at the end of createStrut's construction, since its catch-up may wake a run): `settled(on)` is `settled(id)`, `cancelled(on)` cancels the task, and an `onSettle` listener wakes each settled task's run (answered, expired or cancelled); a run that ends cancelled while live cancels the tasks it left open (`cancelRun`, from the end hook, `RunEndInfo.status`), a run that fails keeps them for a resume. `ensure` takes `{ control, resolveFiles }` beside its input: `deps.refusal(control)` refuses a run tree (`refused:`), and `resolveFiles` runs only when the task is MADE. files.ts: `taskFilesRoot`, `resolveTaskFiles` (what the `human` step resolves `files` with). routes.ts: the STAFF's routes (§6), full scope only, reads included — `GET /tasks/types`, `PUT`/`DELETE /tasks/types/:name`, `GET /tasks/workers[?status=]`, `PUT /tasks/workers/:actor`, `PUT`/`DELETE /tasks/workers/:actor/grants/:type`, `GET /tasks[?type=&status=&workflow=&runId=&before=&limit=]`, `GET /tasks/:id`, `POST /tasks/:id/take-back { worker?, why }` (`409 released` past the hold); a refusal `{ error, code }` (`400`, `404`, `409 in_use`); specs/API.md §22. tasks.test.ts runs one suite over both; bag.test.ts what a step finds on the bag (a registry, a custom step and an agent's tool call: `ensure` alone); steps/core/human.test.ts the step and the source; worker-door.test.ts the door end to end (a run parks, a signed-in visitor's page answers it through `/public/mcp`, the run finishes; a paid answer's run counts its pay, `task/me` shows it held then withdrawable, and only staff take it back) and §13's row 3

### `src/steps/lib/task/`

the WORKER's door to the task store (plans/human-steps.md §5.1), thin over `ctx.services.tasks` — on their OWN call's bag, the worker's calls alone (`TasksService.worker`, which the app door's `dispatch` adds for a `worker: true` step on `POST /mcp` and `POST /public/mcp`, `workerServices`; the shared bag carries `ensure` alone, plans/human-steps.md §9.2): task/next { type?, wait? } (the oldest open task of a type the worker holds that the CALLING app draws — `wrong_app` for another app's — or `{ none: true }`; `wait` ≤ 25 s holds for one), task/submit { lease, answer }, task/skip { lease, reason? }, task/file { lease, path } (one of the task's `files`, as `run/files` answers), task/me (status, the types held in this app with what an answer earns, and the worker's `balance` — held, withdrawable, total, plans/human-steps.md §8.1; a first call writes the viewer `new`). Each is `worker: true` (`StepDef.worker`: it decides from its own caller): the worker is `ctx.actor` in `ctx.app`, never an input; refused without either, and refused as anything but an app page's own call (a one-step run, never a workflow's step or an agent's tool, `_shared.ts` `workerCall`). On the app door a worker's step is never kept as a run (`keptFromApp`, no claims read); a signed-in visitor's page reaches one its app grants (`signedInRefusal`'s `worker` rule), an anonymous one is refused; not a visitor's daily write; the app monitor counts their `volume` per viewer
