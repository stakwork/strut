# The public view, visitors and public runs

What a person shows anyone (`/public/*`), signed-in visitors, and what anyone may run or call here.

This file is the reference for one area of strut; [AGENTS.md](../AGENTS.md) is the
index. A change in this area updates this file, not AGENTS.md.

## Files

What each file and folder in this area is, in the order of the tree.

### `src/visitors.ts`

SIGNED-IN VISITORS (plans/app-repos.md §5; work item 4): the seam and the rules, no routes (createStrut mounts `/visitors`, `/visitors/challenge`, `/visitors/session`, `/visitors/lnurl` — open to anyone). VERIFIERS: `ecdsa-p256` (a WebCrypto key → `p256:<compressed hex>`), `ecdsa-secp256k1` (an LNURL-auth linking key), `bip340` (Nostr) and `ln-message` (a Lightning signed message exactly as Sphinx makes one — sphinx-rs `sign_bytes`: `[31 + recid] ‖ r ‖ s` over sha256d("Lightning Signed Message:" ‖ challenge), the recovered key held to the `key` sent; vectors from the real signer in kit/src/wallet/vectors.json) → `secp:<x-only hex>`, one person whichever way the key signed; `webauthn` named, not built. METHODS (`METHOD_INFO`, what a box names in `signIn`): `key`, `ticket` (a host's `POST /auth/ticket { role: "visitor" }`, traded at `POST /auth/session`), `lnurl` (LUD-04 by QR: the page registers its spent challenge, `createLnurlLogins` keeps the `k1` five minutes, the wallet calls back, the page takes the session with the challenge's hash — `k1` alone buys nothing), `nostr` (NIP-07 + NIP-98, `nostrSigner`; root key only, not offered where `visitorKey: domain`, `offeredMethods`), `sphinx` (the person's Sphinx account through the wallet that holds it — Peel, asked by the host page with specs/WALLET.md §1.2's `sign_in`; `{ challenge, method, key, sig, address? }`, verified by `ln-message`; the wallet derives the domain's child key itself; `address`, the account's Sphinx address, rides in the session's signed claims only when its pubkey is `key` (`keptSphinxAddress`; a domain's child key, another method or an older Peel keeps none, and signs in all the same), refreshed by each sign-in, never in the response; the `/public/mcp` door hands it to a worker step on that call's bag as `services.sphinxAddress`, as it hands the actor — never from the step's input. In `visitors.ts` and `visitor-address.ts`, "address" otherwise means the client IP for the budgets). The sign-in routes answer CORS `*` (a host page on another origin signs a visitor in, specs/API.md §17.9). LIMITS (ruled 5): writes and launches per actor per UTC day (`DEFAULT_VISITOR_LIMITS`, the public view's `visitors.limits` over them), and `ADDRESS_VISITOR_LIMITS` per address on top, whatever `limits` says (`createVisitorBudget`, in memory). The RULES a signed-in visitor's `step_run` is held to over the anonymous one's (`signedInRefusal`): its own `app/state`, `app/report-error`, graph writes (the door checks the declared type) and `graph/find` on the app's declared types, `run/launch` and the run reads of a granted workflow whose closure spends nothing (`runnableCan`), never a `namespace`; a spending one only as `runnable`; a WORKER's step the app grants (`worker: true`, the `task/*` steps: plans/human-steps.md §5.2), the visitor the worker — never an anonymous visitor's, and not a daily write (`visitorWrite`). In createStrut's `/public/mcp`: the visitor's bag per call (`dataDir`; a reader that also sees the app's declared types; a writable graph for a write or `graph/find` alone), writes KEPT as runs with the actor, a direct launch takes `input` and `key` alone (`visitorRuns`'s `own`: the visitor reads back its runs by `actor`)

### `src/public-surface.ts`

the PUBLIC SURFACE — the PUBLIC VIEW in the UI, never a "publish" (plans/public-surface.md §2, §4): what a PERSON chose to show anyone, live and read-only — who may SIGN IN to its apps (`visitors: { signIn, visitorKey?, limits? }`, plans/app-repos.md §5; absent, `sphinx` once an app is public (`DEFAULT_SIGN_IN`, `signInOf`), `signIn: []` none; a served box writes it from serve.yaml; elsewhere the Public view tab's Sign-in section) — Concept roots (the subtree under each by PARENT_OF), workflows (`runs: true` adds their runs, input whole), steps (with the `_` helpers their relative imports reach, `stepHelpers`), node types, apps (`reads`, `domains`: the app half is item 2), and what anyone may RUN (`runnable`, plans/paid-runs.md §2: `{ kind: workflow | step, name, base?, markup?, capUsd?, dailyCapUsd?, results? }`, dollars, independent of `workflows` and `steps`; `runnableShapeProblem` checks its fields and numbers, an older file reads as none; `PublicSurfaceService.runnable(kind, name)` finds one). One record, `<dataDir>/public.json` (`readSurface` / `writeSurface` / `surfaceProblem` / `normalizeSurface`), written by `PUT /public-view` (full scope) and by nothing else but an ADMIN's yes to `app/make-public` (src/public-view.ts), which writes through the route's own save (createStrut's `savePublicView`). `createPublicSurface` is what the routes read through: the public Concept trees (walked live from each root, reused 30 s), each public run's named nodes (`step.end.nodes`, kept per finished run in `<dataDir>/public/run-nodes/`), `visible(ref_id, type)` (§4: under a public root, named by a public run, or of a public type), and `reader()`, a GraphReader that answers only with visible nodes and edges between two of them (`publicReader`; the namespace registry refused). `publicEvent` / `publicSummary`: a run as a visitor reads it — no actor, principal, job, `startedBy`, callback or MCP origin; a session as a `/public` transcript link. A visitor's `step_run` (§5): `visitorRefusal` (an app in the view at the version it serves; run reads on public workflows, with runs; `run/launch` of a workflow anyone may RUN that the app grants (plans/paid-runs.md §10, item 10) and the run reads of one, its visit's own; `VISITOR_GRAPH_READS` through the filtered reader; the app's `reads`; any other launch, cancel, jobs, `app/*` and graph writes refused), `visitorRuns(inner, { surface, visitor?, visitRefusal?, launch? })` (the runs capability held to reads, records scrubbed, deliverable links under `/public`, a job run's files closed; a runnable workflow whose runs are not public reads only the runs this VISIT launched — `visitorOfVisit`, a hash of the `x-strut-visit` secret its host sends, recorded as `run.start.visitor` and on the summary, a `run/list` filter (`RunListQuery.visitor`); a launch with no visit or a malformed one is refused before anything is admitted or charged, `visitProblem` (`visit_required:`) — as far as the item's `results` lets its launcher (`output`: `outputOnlySummary`, the files `declaredPaths` names; `run`: everything), and its definition as `GET /public` lists it; `launch` is the public launcher's — `PublicDoors.launch`, src/public-routes.ts — read into the tool's result by `visitorLaunchResult`: `{ runId, existing?, credit? }` (never the run token), `{ payment_required: { macaroon, invoice, usd, sats, rate, description, expires, remaining_usd?, reason?, carries? } }` for a priced one no credit covers, else a thrown sentence; the credit token rides on the `/public/mcp` request's own `Authorization: L402`, never an argument or a result; cancel stays closed)

### `src/public-routes.ts`

the `/public/*` routes (decision 13, ruled): a route family of its own, answered from the surface alone WHATEVER the gate's mode, so a host gate in front of an unkeyed strut passes the prefix by path and nothing else opens; a route nobody mounted there does not exist there. Paths mirror the private reads (`/public/workflows/:name/flow`, `…/runs/:runId/events`, `/public/steps/:type/source`, `/public/concepts/:name`, `/public/graph/nodes/:ref_id`), shapes minus who and where; `/public/apps[/:name[/document]]` the public apps, each at the version the view serves, the document carrying a VISITOR's identity (`publicAppIdentity`, auth.ts: signed over `public-app:`, so it opens `POST /public/mcp` and nothing else) and `<meta name="strut-public-view">` (the kit's `useHost().public`), and `<meta name="strut-public-runnable">` — the granted workflows a visitor may start, each `{ name, results }` under the name the app grants it by (resolved package-first, createStrut's `workflowInApp`), `useHost().runnable` and `.results` (`withPublicIdentity`, src/apps/build.ts). `GET /public` carries `host: { remote: 1 }` (`PUBLIC_HOST`: its apps may be hosted by another strut UI, specs/API.md §17.9); CORS `*` + preflight — set again after the handler on an answer that is a Response of its own (`POST /public/mcp`'s MCP door), so a visitor's page another strut UI hosts reads it (specs/API.md §17.9); the preflight allows `authorization`, `x-strut-visit` and MCP's `mcp-protocol-version` / `mcp-method` / `mcp-name` — a per-address budget for reads and the visitor door (`PUBLIC_REQUESTS_PER_MINUTE`, `visitorAddress` — src/visitor-address.ts; a request whose `budgetKey` names another budget counts there instead: createStrut's, an ACTIVE worker's visitor session, `TASK_REQUESTS_PER_MINUTE` 240 a worker, plans/human-steps.md §5.2), `PUBLIC_PATH` (the reads the gate opens) and `PUBLIC_POST` (the POSTs it opens by name: `/public/mcp`, a launch, its cancel, a tool's call, `/public/credit` and `/public/credit/claim`). PUBLIC RUNS (plans/paid-runs.md items 3 and 5): `POST /public/workflows/:name/run { input?, key? }` → `202 { runId, token, credit? }` — the address's own budget (`PUBLIC_LAUNCHES_PER_MINUTE`, 60), the item (404 unless `runnable`), the drain, the body (256 KB, `input` and `key` alone, the `input:` block), a priced item's CREDIT TOKEN read before the caps (`Authorization: L402 <macaroon>:<preimage>`, or `LSAT`: `credit.verify` — 401 `invalid_token` — and `tokenRefusal`, src/l402.ts — 403 `token_not_for_this` / `token_over_max_charge`; its id scopes the `key`), the caps (src/public-runs.ts `admit`, 429 with `Retry-After`), the PRICE (§4, §5: no token, one past its end or replaced, or one whose free credit is under the reserve is a 402 — `credit.challenge`, for the shortfall carrying the token when no holder narrowed it, else the whole reserve, `reason` short | expired | replaced; a token's first use asks the wallet, 503 when it cannot; else `admission.hold` sets the reserve aside, and the same token and `key` as an earlier launch return that run), then `launches.launch` (createStrut: `launchDetached` with `origin: "public"`, no actor, no params, the host's `publicRuns.principal` else the owner, the run's cap, the credit token's id as `run.start.credit`, a visitor page's visit as `run.start.visitor`). That order is ONE function, `launch(PublicLaunchRequest) → PublicLaunchOutcome` (status, body, headers as data), which `publicRoutes` returns (`PublicDoors`) so a visitor's app page (`run/launch` on `POST /public/mcp`, plans/paid-runs.md §10) goes through it too, sharing the address's budget, its key scoped by the visit — and so does an agent's `run_workflow` (src/public-agents.ts); `PublicDoors` also hands out `call` (a tool's call: the calls' per-address budget, the drain, the body, then src/public-tools.ts `call` — what the route is a thin wrapper over), `run` (the launcher's view by its run token, `wait` held; once the run ended it waits at most 2 s for the charge and then answers `charge_pending: true` rather than holding the wait), `credit` and `claim` (the credit routes as data — the balance now with `runs`, the runs and calls its token paid for, read off its ledger entries, each run with its run token), `runnable` and `listing` (`GET /public`'s answer) and `overBudget` (the address's `/public` budget, for `GET /llms.txt`), each answering `{ status, body, headers? }`; `PublicLaunchRequest.defaultKey` is the key a PRICED launch with none of its own goes under, made from the parsed input (the outcome's `key`), never a free one's; CREDIT (src/public-credit.ts): `GET /public/credit` (a token's balance, its first use if it had none), `POST /public/credit { usd } | { sats }` (a 402 for more credit; a token presented un-narrowed carries; 404 when nothing here is priced), `POST /public/credit/claim` (the macaroon alone: pending, expired, or settled with the preimage — a phone wallet's payer; the token's first use recorded from that answer); the two GET-less ones 404 on a strut with no `L402_ROOT`; a 401 carries `WWW-Authenticate: L402 error="…"`, and `WWW-Authenticate` / `Retry-After` are exposed to a browser's script; the RUN TOKEN (`publicRunToken` / `isPublicRunToken` / `presentedRunToken`, auth.ts: an HMAC over `public-run:<workflow>/<runId>`, `?t=` or Bearer) opens that run's `/public` reads — the launcher's view (`?wait=` ≤ 55 s, `charged` once charged — the ledger's `chargeOf` — the declared artifacts with `/public` links) and, by the item's `results`, the declared files alone (`output`) or the events, transcripts and every file (`run`) — and `POST …/runs/:runId/cancel`, never a private route nor another run. PUBLIC TOOLS (item 6): `POST /public/steps/:type/run { config }` → `200 { output, credit? }` — the address's own budget (`PUBLIC_TOOL_CALLS_PER_MINUTE`, 120) and the drain, the body (256 KB, `config` alone), then src/public-tools.ts `call` (specs/API.md §17.7). `POST /public/mcp` itself is createStrut's: `buildAppTools` with `visitor` (the public identity, `visitorRefusal` after the grants on the workflow name resolved in the app's package — `inAppPackage` — nothing kept) over a bag of reads alone — `http`, `secrets`, the graph's filtered reader, `visitorRuns` with the request's visit (`x-strut-visit`, which the preflight allows) and the launcher, its `Authorization` the credit token. What a host does with a `payment_required` is specs/API.md §17.6. The person's door is `/public-view` (GET / PUT, `needs` — `?app=&version=` — `runnable`), behind the key; an app it adds is HELD at its version; an agent's ask is `app/make-public`, an admin's yes, through the same save (src/public-view.ts); a PUT checks every `runnable` item (src/public-runnable.ts) and refuses naming each. `GET /public` also lists what anyone may run (`runnable`: price, reserve, input, recent runs — never its definition unless that is public too). specs/API.md §17

### `src/visitor-address.ts`

WHO a public request is from (`visitorAddress`, the key of every per-address budget): the socket's peer, or — only when that peer is a TRUSTED proxy — `x-forwarded-for` walked from the right past trusted hops. Default set loopback, link-local, private; `STRUT_TRUSTED_PROXIES` / `createStrut({ trustedProxies })` replaces it. No socket is `unknown`

### `src/public-runs.ts`

PUBLIC RUNS' policy (plans/paid-runs.md §3, §5, §6, §7; items 3 and 5): `createPublicRuns({ ledger, store, file?, maxInFlight, price? })` → `strut`'s one service — `admit(item, { workflowCapUsd, key, scope })`, SERIAL so the check and counting the run are one step (twenty launches at once never pass a cap): a `key` the same address sent for a run in flight returns it, then the server's limit on public runs in flight (`STRUT_PUBLIC_RUNS_MAX`, `publicRuns.maxInFlight`, 10), then the item's `dailyCapUsd` (`dailyRoom`: the ledger's `today(subject).cost` plus the cap of each of its runs in flight; a run is admitted while what is left holds its FULL cap, never a sliver the gateway would stop partway, and past that the last of the day goes to one run alone with what is left; else 429, `Retry-After` until midnight UTC when the day is spent); mints the run id and writes the run to `<dataDir>/payments/public-runs.json` before the launch; the run's CAP is the smaller of the item's per-run cap (`perRunCapUsd`, public-runnable.ts: its `capUsd`, else a tenth of its daily cap, `DAILY_CAP_SHARE` — so ten run at once, never one) and the workflow's own (`resolveRunCap`), or for the day's last run what is left (`RunOptions.maxCostUsd`); `release()` for a refusal after the caps (the 402), which frees a hold it made (a charge of nothing); `hold({ token, price, reserve, key? })` — a priced run: the token, the price of that moment and the reserve on the run's entry, ON FILE, then the ledger's `hold` under the run id the caps minted (refused, or naming another run — the same token and key — lets the admission go). `track` (a durable resume of one, with its `run.start.credit`), `ended` (the run end's charge: the ledger's `charge` — with the entry's token and price, by the rule, else no token, a charge of nothing whose cost counts in `daily` — then off file and out of flight; a run that never started has its hold freed; idempotent; a charge that fails is tried again after `SETTLE_RETRY_MS`, never left until the next boot), `charged` (the ledger's `chargeOf`: the launcher's view), `load` (boot: every run on file counts in flight; a file that does not read is moved aside, `.unreadable-<ms>`, and the boot goes on) and `reconcile(live, { holds })` (after auto-resume: what is not live is charged — its summary, else its log, a run cut off and never resumed as an error at what its log spent — a run with no `run.start` dropped; with `holds`, also every open `workflow:` hold in the ledger whose run is neither on file nor live, at the item's price now, `price`; a `step:` hold is src/public-tools.ts's)

### `src/public-tools.ts`

PUBLIC TOOLS (plans/paid-runs.md §3's table, §6 "A tool", decision 15; item 6): one runnable STEP anyone may call, answered at once. `createPublicTools({ ledger, surface, registry, services, credit?, draining?, principal? })` → `call({ type, config?, presented?, address })` — the ONE function the route and item 8's MCP `call_tool` share — answering `{ status, body, headers? }`: the drain (503), the item (404 unless `runnable` as a step, and item 2's save checks asked AGAIN, `stepRunnableProblem` in src/public-runnable.ts: the registry changes after a save), the config (an object parsed by the step's own input schema, 400 naming the field; one naming a secret, reach.ts `secretNamesIn`, 400), a priced item's token as a launch's (`credit.verify`, `tokenRefusal` with `step:<type>`: 401 / 403), the caps (serial: the address's share of calls in flight, `PUBLIC_TOOL_CALLS_PER_ADDRESS` 5, the server's, `PUBLIC_TOOL_CALLS_MAX_IN_FLIGHT` 20, then the item's `dailyCapUsd` when set, by a run's rule — `perRunCapUsd` for the call's cap and public-runs.ts `dailyRoom` for whether it fits, so a daily cap with no `capUsd` admits ten at once — 429), the price (402 as a launch's, carry-over included; `credit.use`; `ledger.hold` under a minted call id, no key), the call (`runSingleStep` — never `runStep`, which keeps a run with claims — with the caller's config as the run's INPUT and the step's config `inputTemplates`, `{ k: '{{ input["k"] }}' }`, a sole expression the runner returns as it is, so nothing a stranger sends is evaluated; `origin: "public"`, no actor, the host's public principal, the item's cap as `maxCostUsd`, a `RunController` force-cancelled past `PUBLIC_TOOL_CALL_TIMEOUT_MS`, 60 s → 504; inside `asPublicCall`, src/public-call.ts; nothing reaches the run store, the ledger entry is its record), the charge (`ledger.charge` by the rule, which never passes the hold's reserve: base + markup × the `withUsage` cost, none its base; a throw, a time-out or a result over 5 MB (`PUBLIC_TOOL_RESULT_MAX_CHARS`), its cost and no base, 500 `step_failed` / `result_too_big` or 504; never past the reserve nor what the token holds; free: a charge of nothing; refused by the ledger, tried again now and then every `CHARGE_RETRY_MS` for an hour), `credit` on the answer (`charged_usd`, remaining, expires). `inFlight()` — what the drain's `idle` waits on; `reconcile()` — boot, beside item 5's: every open `step:` hold whose call is neither in flight nor waiting on a charge here is freed (the call never answered; a charge of nothing); `close()` stops the charge retries. `publicToolServices(bag, { graph, http, runs })` — the ALLOWLIST bag: the visitor's (`secrets`, `visitorRuns`) with `readOnlyGraph(g)` (createStrut passes `graphView(graph, graphReaders, "jobs")`: its reader, `dialect` and schema reads, a raw `query` that READS — the write keyword check, then the engine's own read-only path, a READ transaction on Neo4j or `lbug.readOnly()` on Ladybug, gated like any view's (`assertRawQuery`) and carried as the view's unscoped query (scope.ts `carryScope`), so `graph/find` holds to the lists — every write refused: `nodes`, `edges`, `tx`, the schema's create/extend/delete; no `bolt` / `lbug`), no graph a stand-in that refuses every read (never `graphCtx`'s Neo4j-from-env fallback), and `guardedHttp()` (src/guarded-http.ts, shared with the `remote/*` steps; SSRF: aieo's `validateFetchUrl` on every URL and every redirect, followed by hand, no loopback / private / link-local / reserved address nor a name resolving to one; a hop to another origin drops `authorization`, `cookie`, `proxy-authorization`, `withoutCredentials`, as fetch does; each request ≤ `PUBLIC_TOOL_HTTP_TIMEOUT_MS`; DNS rebinding between the check's lookup and the fetch's is a known limit); no `onRunEnd` / `onRunEvent`, so a call is never projected, verified or sunk

### `src/public-agents.ts`

AN AGENT AS A BUYER (plans/paid-runs.md §10 "An agent over MCP", item 8): `buildPublicAgentTools({ doors, who, authorization, publicUrl })` — the five tools `POST /public/mcp` serves beside a visitor page's app-only `step_run`, for an agent with no account: `list_public` (`GET /public`'s `runnable` with `call_with`), `run_workflow { workflow, input?, key?, payment?, wait? }` (through `PublicDoors.launch`, so the address's budget, the drain, the body, the caps, the price and the key are the HTTP door's; a PRICED launch with no key of the agent's goes under `defaultLaunchKey` — the workflow and the input AS ITS `input:` BLOCK PARSED IT, keys sorted (`canonicalJson`), applied by the launcher's `defaultKey` and scoped by the credit token — so the same launch sent again while its run is in flight is that run; a FREE launch gets a key only when the agent passes one: its scope is the address, which a hosted agent's vendor shares; the first yield is the run's handle `{ run_id, token, url }`), `call_tool { type, config?, payment? }` (`PublicDoors.call`; no key: a priced call is charged once it ran, even when the client gave up), `get_run { workflow, run_id, token, wait? }` (`PublicDoors.run`) and `get_credit { payment? }` (the balance and `runs`: the runs and calls the credential paid for, newest first, each run with its run token and url — the WAY BACK to a run whose answer was lost after it ended, which a key no longer finds; with a macaroon alone, the CLAIM). Every tool's description says to read get_credit before calling again after a timeout or a dropped answer. A priced call with no credit answers a RESULT, `{ payment_required: { macaroon, invoice, usd, sats, rate, description, expires, remaining_usd?, reason?, carries? }, next }` (`paymentRequiredResult`), never an error; the credential is the call's `payment` (`"<macaroon>:<preimage>"`, or the macaroon alone, claimed first — settled, its whole `credential` comes back on the answer), else the connection's own `Authorization: L402`. Nothing is kept between requests: the credential works on any connection. Every tool answers within `AGENT_DEADLINE_MS` (45 s, under the MCP SDK's 60 s default request timeout, which progress resets only when a client asks; `wait` ≤ 45): a launch still starting, a run still going (its handle and `next`) or a call still going (`still_running`, "check get_credit") answers what it has. Progress every `AGENT_PROGRESS_EVERY_MS` (5 s; the door sends a yield's progress when the next arrives). A run reads as still going by its own STATUS, so one that ended with its charge pending says so and stops (`charge_pending`). No builder cap on these results: a call's output comes back whole (the door's 5 MB), a run's output over `RUN_OUTPUT_INLINE_MAX` (100k chars) is left out with the run's HTTP url (`output_omitted.read_at`, the token on it). `publicMcpInstructions`; `publicLlmsTxt` — `GET /llms.txt` on a strut whose public view has anything (llmstxt.org): what anyone may run and its price (`priceWords`), its input, how an agent runs it (the MCP door, left out when `enableMcp` is off, or plain HTTP) and pays, and what else is public to read; `runnableSection` is the same list an INDEX strut that also sells appends to its own page. createStrut's `llmsPage` builds either page at most every 30 s per base URL (`LLMS_TXT_CACHE_MS`) and counts it against the address's `/public` budget (`PublicDoors.overBudget`)

### `src/public-call.ts`

a PUBLIC CALL's scope (item 6): `asPublicCall(fn)` runs a public tool's call in an AsyncLocalStorage scope; `stepFailed(text)` — what a lib step answers a failure through when it answers one as TEXT for a model (`graph/*`'s `errText` and its inline "node not found" / "… failed" returns, `sheets/*`'s `errorResult` and catches) — returns the text as before, and inside a public call throws it as a `StepFailure`, so the call is charged as the failure it is (decision 24); a `catch` that wraps one rethrows it as it is

### `src/guarded-http.ts`

the http capability for a STRANGER's URL (SSRF), shared by a public tool's bag (src/public-tools.ts) and the `remote/*` steps (src/remote.ts): aieo's `validateFetchUrl` on every URL and every redirect, followed by hand (at most 5), no loopback / private / link-local / reserved address nor a name resolving to one; a hop to another origin drops `authorization`, `cookie`, `proxy-authorization` (`withoutCredentials`), as fetch does; each request ≤ its `timeoutMs`; `allowLocal` (the remote steps' `STRUT_REMOTE_LOCAL=1`) lets loopback and private addresses by, never a link-local one or a name resolving to one.
